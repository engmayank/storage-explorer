The one chain to remember

A Pod never talks to a disk. It names a claim. The claim finds a volume. The volume points at real storage. A StorageClass lets Kubernetes create that volume on demand.

Podvolumes: names a claim, volumeMounts: picks the path
→
PVC"I need 10Gi, ReadWriteOnce." A request, namespaced.
→
PVThe real volume. Cluster-wide, no namespace.
→
DiskNFS share, cloud disk, local SSD, Nutanix volume
StorageClass sits beside the chain. When a PVC arrives and no PV matches, the class tells a CSI driver to create one. That is dynamic provisioning, and it is how most real clusters work. Solid outline = developer owns it. Dashed outline = admin or driver owns it.

Three rules that settle most exam questions

PVs have no namespace

PVCs, Pods and most volume sources do. A PVC can only be used by Pods in its own namespace.

Binding is one to one

One PVC binds to exactly one PV, matched on size (at least), access mode, storageClassName and selectors. A bound PV is taken, even if it is bigger.

Make a PV file only for static storage

If a default StorageClass with a provisioner exists, write only the PVC. Write a PV yourself when the task hands you a path, an NFS server, or says hostPath.
